## Preguntas frecuentes

**¿Playwright o Cypress?** Los dos automatizan el navegador. Playwright lo controla desde fuera (varias pestañas, varios navegadores, API y navegador en la misma prueba); Cypress corre dentro del navegador, con una experiencia interactiva muy pulida. Comparación completa en [la hoja de E2E](02-e2e.md).

**¿Prueba de API con Playwright o con Postman/Newman?** Con Playwright si la prueba vive junto al código y comparte fixtures con las E2E; con una colección de Postman si el equipo ya diseña y documenta la API en Postman y quiere ejecutarla desde la línea de comandos con Newman. Ver [la hoja de APIs](03-apis.md).

**¿Mock, stub o entorno efímero?** Un mock o un stub sustituye una dependencia para probar una pieza aislada; un entorno efímero levanta la dependencia real, limpia, para cada ejecución. Ver [fundamentos](01-fundamentos.md), [APIs](03-apis.md) y [CI/CD](04-ci-cd.md).

**¿Reintentar una prueba que falla a veces?** Los reintentos dan señal de que la prueba es inestable, no la arreglan. Ver [la hoja de calidad](05-calidad-e-ia.md).

**¿100 % de cobertura es suficiente?** No: dice qué líneas se ejecutaron, no si alguna aserción las comprueba. El mutation score lo mide. Ver [la hoja de calidad](05-calidad-e-ia.md).
